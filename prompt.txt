1. Obiettivo del Progetto

M22C Secure Suite è un'applicazione web client-side single-file (HTML5/JavaScript) progettata per garantire la cifratura multi-livello e la frammentazione geometrica dei file in totale privacy locale (zero-server).

Ambiente di esecuzione: Browser web moderno (ottimizzato per Google Chrome).

Linguaggio e API: JavaScript ES6+ e HTML5, con utilizzo nativo della Web Crypto API (AES-256-GCM, PBKDF2-HMAC-SHA256) e della File System Access API per la gestione dei file.

Librerie esterne: JSZip per l'archiviazione e la generazione dei container .m22c.

Licenza e Credits: Licenza Open Surge; attribuzione "Powered by Benevolo B." con link alla pagina personale ([https://cruelben.github.io/](https://cruelben.github.io/)).

2. Architettura e Struttura

La logica di cifratura e frammentazione segue una pipeline distribuita in tre stadi principali:

Iniezione Header: Inserimento dell'header proprietario M22X all'inizio del file sorgente.

Cifratura di Primo Livello: Cifratura del payload tramite AES-256-GCM con chiave derivata dalla Password 1 (utilizzando PBKDF2 con salt casuale).

Frammentazione Geometrica Ricorsiva (4x4x4): Suddivisione ricorsiva del payload cifrato su 3 livelli (4x4x4), che genera esattamente 64 blocchi binari individuali.

Cifratura dei Blocchi (Stadi 2 e 3): Ulteriore cifratura dei 64 blocchi binari mediante l'uso sequenziale di Password 2 e Password 3.

Fisher-Yates Shuffling e Manifest Tree: Permutazione casuale dell'ordine dei blocchi cifrati tramite l'algoritmo Fisher-Yates e generazione del file di ripristino manifest_tree.dat.

Packaging Container .m22c: Impacchettamento dei 64 blocchi e del file manifest all'interno di 3 archivi ZIP con estensione .m22c (con opzioni di naming casuale o camuffamento grafico).

Interfaccia Utente (UI/UX): Workflow guidato a 3 step con indicatori di stato cromatici (verde per successo, rosso per errore/incompleto), area drag-and-drop per i file e rimozione opzionale dei metadati.

    async function deriveKey(password, salt) {
        const enc = new TextEncoder();
        const keyMaterial = await crypto.subtle.importKey(
            "raw", enc.encode(password), "PBKDF2", false, ["deriveKey"]
        );
        return crypto.subtle.deriveKey(
            { name: "PBKDF2", salt: salt, iterations: 100000, hash: "SHA-256" },
            keyMaterial,
            { name: "AES-GCM", length: 256 },
            false,
            ["encrypt", "decrypt"]
        );
    }

    async function encryptData(data, password) {
        const salt = crypto.getRandomValues(new Uint8Array(16));
        const iv = crypto.getRandomValues(new Uint8Array(12));
        const key = await deriveKey(password, salt);
        const encrypted = await crypto.subtle.encrypt({ name: "AES-GCM", iv: iv }, key, data);
        
        const result = new Uint8Array(salt.length + iv.length + encrypted.byteLength);
        result.set(salt, 0);
        result.set(iv, salt.length);
        result.set(new Uint8Array(encrypted), salt.length + iv.length);
        return result;
    }

    function fisherYatesShuffle(array) {
        const arr = [...array];
        for (let i = arr.length - 1; i > 0; i--) {
            const j = Math.floor(Math.random() * (i + 1));
            [arr[i], arr[j]] = [arr[j], arr[i]];
        }
        return arr;
    }

    function splitBuffer(buffer, parts) {
        const chunks = [];
        const chunkSize = Math.ceil(buffer.length / parts);
        for (let i = 0; i < parts; i++) {
            const start = i * chunkSize;
            const end = Math.min(start + chunkSize, buffer.length);
            chunks.push(buffer.slice(start, end));
        }
        return chunks;
    }

            }

            step3.className = 'step-item status-pending';

4. Scelte Tecniche e Vincoli

Zero-Server Architecture: Tutta l'elaborazione dei dati avvenga in-memory nel browser.

Sicurezza Crittografica: La derivazione delle chiavi impiega PBKDF2-HMAC-SHA256 con 100.000 iterazioni e salt casuale a 16 byte. La cifratura simmetrica usa AES-256-GCM con IV univoco a 12 byte per ogni operazione.

Formato Container .m22c: Il file risultante è un archivio .m22c basato su ZIP contenente la cartella dei blocchi cifrati (/blocks/) e il manifest ordinativo (manifest_tree.dat) necessario alla decifratura.

UI/UX: Sostituzione dei menu a tendina con input drag-and-drop diretti e tracker visivo a tre fasi con colorazione di stato (rosso per errore/incompleto, verde per completamento).

Licenza: Utilizzo esclusivo della licenza Open Surge anziché della solita licenza MIT.

Bug risolti nelle sessioni precedenti: Eliminati i problemi di interruzione dei file input standard di Chrome tramite l'adozione dell'interfaccia Drag-and-Drop nativa e la corretta gestione dei buffer tipizzati (Uint8Array) durante lo splitting dei blocchi.

5. Cosa Resta da Fare

Implementazione modulo di Decifratura completa: Creazione della pipeline inversa (estrazione ZIP, lettura manifest_tree.dat, unione dei 64 blocchi tramite permutazione inversa di Fisher-Yates, decifratura sequenziale Pass 3 -> Pass 2 -> Pass 1, rimozione dell'header M22X e download del file originale).

Ottimizzazione Web Workers: Migrazione della frammentazione 4x4x4 su Web Worker dedicati per prevenire il congelamento dell'interfaccia utente durante la cifratura di file superiori a 50 MB.

Opzione Camuffamento Grafico: Affinamento della funzione per l'incorporamento facoltativo dei container cifrati all'interno di file immagine (steganografia/camouflage).
